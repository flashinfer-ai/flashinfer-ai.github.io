This release makes MoE expert parallelism deployable inside a serving engine, refreshes the Blackwell SM12x fused-MoE kernels behind an FP4 accuracy fix, extends the unified MoE API to MXFP4 W4A8/W4A16 and shared experts, and adds decode coverage for Kimi K3 MLA and for MiniMax-M3 sparse attention under vLLM.

> ⚠️ The SM90 CUTLASS MoE backend added in #3738 is reverted in 0.6.17, together with its two dependents, after a crash reported by a vLLM user. That backend also shipped in v0.6.16 and v0.6.16.post2, so the revert affects upgrades from those releases; a proper fix is expected in 0.6.18.

### MoE expert parallelism production-ready in vLLM

The MegaMoE path in `flashinfer.moe_ep` can now be driven by a serving engine rather than a benchmark script: it supports full CUDA-graph capture and replay, a fused single-launch quantize-and-stage hot path, prequantized weight packs that release the source weights after preprocessing, symmetric-buffer workspaces pooled across layers, and a persistent knob cache that resolves tuned knobs by lookup so no autotuning runs inside the engine. A fault-tolerance rank mask, opt-in per Fleet and available over both NCCL-EP and NIXL-EP, masks and skips a peer that times out during dispatch or combine instead of tripping a GPU trap, so a single dead rank no longer kills the job. Two deployment barriers also come down: the CuTe-DSL runtime floor returns to 4.5.2, the version vLLM 0.25.1 pins, via a mainloop workaround for the codegen regression that made the NVFP4 kernel 34-54% slower on that version; and `BootstrapConfig.device` lets the host framework pin each worker's CUDA device instead of `moe_ep` deriving it from `LOCAL_RANK`, which under a remapped `CUDA_VISIBLE_DEVICES` could bind the wrong GPU.

### Blackwell SM12x fused MoE refreshed, with an FP4 accuracy fix

W4A4 serving on DGX Spark and RTX PRO parts (GB10, SM120/SM121) spent far more reasoning tokens than Marlin at equal benchmark scores. Two bugs in the NVFP4 quantization helpers account for the drift and are now fixed: subnormal e4m3 block scales were decoded with a formula up to 4.5x off from what the tensor core reads, and the precise path (`fast_math=False`) inverted the pack multiplier and quantized everything to zero. A new `input_global_scale` additionally separates the input-quantization scale from the output multiplier, so integrators can pass a checkpoint's weight scale directly instead of folding both jobs into `w1_alpha`. The SM12x fused-MoE families are also synced to current b12x: the NVFP4 W4A4 backend reaches kernel parity across decode and prefill, and the W4A16 family gains cooperative persistent launches, a tensor-core decode path for small batches that folds the top-k sum into the FC2 epilogue, and shape-stable route packing so changing the decode batch size no longer forces a recompile.

### Unified MoE API adds MXFP4 W4A8 and W4A16, shared experts, and SiTU

The unified `MoELayer` API continues to absorb the quantization formats that previously required the legacy flat entry points. TRTLLM-gen MXFP4 weights now run through it against both MXFP8 activations (W4A8) and BF16 activations (W4A16), completing the FP8 series begun with block-scale and per-tensor FP8 in 0.6.16, and per-tensor routed FP8 is wired up and tested. Routing gains an unpacked pre-routed FP4 mode that takes `topk_ids` and `topk_weights` as separate contiguous tensors and forwards them without building packed expert-id/weight pairs. TRTLLM-gen FP4 MoE also picks up shared-expert fusion, extending to FP4 what 0.6.15 added for FP8, and SiTU activation support for MXFP4 x MXFP8 and NVFP4 x NVFP4.

### Kimi K3 MLA decode, and MiniMax-M3 sparse attention under vLLM

Kimi K3's MLA geometry — 96 global query heads against one KV head, TP-local head counts down to 6, speculative query lengths up to 8, and context parallelism for long contexts — was not covered efficiently by the existing Blackwell decode paths. Decode now packs query-token and query-head rows continuously into CuTe-DSL tiles so partial head groups share a tile and only the last tile is padded, adds compact variable-length Q, and extends TRTLLM-gen dense and sparse MLA to non-power-of-two head counts. A native sparse MLA decode path also covers the no-rotary-tail shape (`kv_lora_rank=512`, `qk_rope_head_dim=0`), which was previously rejected as an unsupported MLA dimension. Separately, MiniMax Sparse Attention accepts K/V views split from a paged cache that packs K and V into one content dimension per token — vLLM's KV-cache layout for MiniMax-M3 — which unblocks the vLLM integration on SM120/SM121, and its paged decode calls stop rebuilding a prefix sum the caller already supplies.

### Ulysses sequence parallelism for long-context and video diffusion

Ulysses sequence parallelism, used for video diffusion transformers and other long-sequence attention workloads, gets its head-scatter / sequence-gather all-to-all as a first-class API. A fused NVLink-P2P kernel folds the Ulysses layout permutation directly into the cross-GPU writes over CUDA IPC, replacing the usual permute, NCCL `all_to_all_single`, permute sequence with a single coalesced push, behind a topology-aware public API that falls back to NCCL when P2P is unavailable.
