# Entry format

Jekyll skips files here whose names start with `_`, so this file is not a
release entry and never reaches the built site.

One file per release, `<tag>.md`. Normally generated by
`scripts/import_release.py <tag>`, which reads the GitHub release, drops the
auto-generated changelog, and writes the file below.

```markdown
---
tag: v0.6.17
date: 2026-08-11 05:09:14 +0000
---

One-paragraph summary; rendered as the lead.

### Section title

Body text.

<ul class="pr-list">
<li><a href="https://github.com/flashinfer-ai/flashinfer/pull/1234">#1234</a> <span class="pr-title">PR title</span></li>
</ul>
```

- `tag` and `date` are the only required fields. Entries sort by `date`,
  newest first, and `tag` becomes the heading and the `#v0-6-17` anchor.
- Sections start at `###`. The page spends `<h1>` on its own title and `<h2>`
  on the version.
- Link to a release with its version anchor, `#v0-6-17`. Section headings get
  ids generated per entry with no cross-entry dedup, so two releases sharing a
  section title would produce the same id; treat heading anchors as unstable.
- PR references use the markup above rather than a Markdown list: bare `#1234`
  auto-links on GitHub but not here, and the row layout is styled in
  `_sass/releases.scss`.
- A `> ⚠️` blockquote renders as a callout, for anything a reader must act on.
