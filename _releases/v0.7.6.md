FlashInfer v0.7.6 brings NVFP4 and MXFP8 MoE to Rubin and places expert weights on each die of dual-die Rubin GPUs, and extends the batch-invariant mode to linear attention, token sampling and more MoE formats on Blackwell and Rubin. Linear-attention and Mamba2 kernels work directly on a serving engine's state pool. Blackwell adds DeepSeek-V4 sparse MLA and token-sparse attention over NVFP4 KV caches, long-context paged prefill on H100 and Blackwell gets faster by default, and RTX PRO 6000 and Jetson Thor gain DeepSeek sparse MLA, expert-parallel MoE and Gated DeltaNet kernels.

### NVFP4 and MXFP8 MoE run on Rubin, with expert weights placed on each die

Expert-parallel MoE on Rubin adds an NVFP4 MegaMoE through `MoEEpLayer` (`sm107_nvfp4_nvfp4_bf16_cake`), and the CuTe DSL fused MoE accepts `quant_mode="mxfp8"` on SM107, including ClampedRelu2. On dual-die Rubin GPUs, the NVFP4 MoE (`localized_weights=`, with `split_fp4_moe_weights_by_locality_domain`) and the MXFP8 MoE (`localized_options={"fc2_split": "k"}`) split each expert across the two dies so that each die reads weights from its own memory. Opt-in helpers do the same for the FP8 grouped GEMM weights (`cake_batch_deepgemm_fp8.localize_weights`) and the Gated DeltaNet decode state (`localize_gdn_decode_state`).

### Batch-invariant mode covers linear attention, token sampling and more MoE formats

With `batch_invariant=True`, `recurrent_kda` and `chunk_gated_delta_rule` return the same bits for a token in prefill, chunked prefill and decode, and `sampling_from_probs`, `sampling_from_logits` and the top-k, top-p and min-p samplers draw the same token for a row at any position in the batch, keyed by a per-row `seed` and `offset`. `MoELayer` adds `BatchInvariantFp8PerTensorConfig`, the expert-parallel MegaMoE takes `batch_invariant=True` for BF16, NVFP4, MXFP4, MXFP8, W4A16 and W8A16 weights, and the new `mm_mxfp8_mxfp4` GEMM runs in the batch-invariant class. All of these run on SM100, SM103 and SM107.

### Linear-attention and Mamba2 kernels work on the serving engine's state pool

Mamba2 prefill (`ssd_combined_fwd(backend="cake")`) reads initial states from, and writes final and checkpoint states into, a caller-owned state pool indexed by slot, with an explicit `state_dtype`, on SM100, SM103 and SM107. Gated DeltaNet prefill adds opt-in long-sequence paths: context-parallel paged prefill (`chunk_gated_delta_rule_paged`) and an exact sequence split (`use_affine_split=True`) that spreads one or two long sequences across the GPU. Gated DeltaProduct decode runs on SM107 and accepts an FP16 state pool with stochastic rounding on SM100 and SM103.

### DeepSeek-V4 sparse MLA and token-sparse attention read NVFP4 KV caches on Blackwell

DeepSeek-V4 sparse MLA prefill runs on an NVFP4 KV cache on SM100 and SM103 (`trtllm_batch_decode_sparse_mla_dsv4(..., kv_cache_format="nvfp4")`, with queries packed by `cake_dsv4_nvfp4_pack_query`), which covers the 256K-context compressed layers. Token-sparse attention over an NVFP4 KV cache converts only the selected keys to FP8, once per request and under CUDA graphs, through `gather_nvfp4_kv_cache_by_position` and `compact_nvfp4_kv_cache`. `qsa_sparse_paged_attention`, the gated sparse paged attention used by Qwen QSA models, is a stable API and ships prebuilt in the wheel for SM80 through SM90.

### Long-context paged prefill gets faster by default on Blackwell and H100

`BatchPrefillWithPagedKVCacheWrapper(backend="auto")` routes qualifying long paged prefills to cuDNN. On B200 and B300, FP16 causal prefill uses the same routing as BF16 when cuDNN Frontend 1.33 or later and cuDNN 9.24 or later are installed. On H100 80GB, BF16 and FP16 prefill with head dimension 256 and page size 16 moves to cuDNN once a request is large enough, causal or not; smaller requests keep their current kernels.

### DeepSeek sparse MLA, expert-parallel MoE and Gated DeltaNet reach RTX PRO 6000 and Jetson Thor

On SM120 GPUs such as RTX PRO 6000, `SparseMLASm120Wrapper` adds a split-KV FP8 sparse MLA decode for DeepSeek-V4.1, chosen by `impl="auto"`, and `run_mega` fuses query RoPE, attention, inverse output RoPE and FP8 output quantization into one launch. `MoEEpLayer(nosync=NosyncOptions())` runs decode-size expert-parallel MXFP4 MoE on SM120 through one fused dispatch, GEMM and combine kernel, and block-scaled FP8 linear layers on SM120 and SM121 use small-batch tiles at decode sizes. Gated DeltaNet prefill (`chunk_gated_delta_rule`) runs on Jetson Thor (SM110) with CUDA 13.

> **⚠️ Upgrade notices**
>
> - Install `nvidia-cudnn-frontend>=1.33.0`. Projects that cap the cuDNN Frontend below 1.33 must lift the cap to use this release.
> - The CAKE training kernels are removed: the `flashinfer.cake_<op>_{det,nondet}_train` modules with their `_kcp` variants, and `grouped_mm_bf16(backend="cake")`. Move training callers to cuDNN Frontend, or to `radixark/miles-ext-kernels`, which carries all 13 kernel families.
> - `decode_cp_a2a_lse_reduce` takes destination-major inputs: `partial_o` as `[batch, cp_size, heads, head_dim]` and `partial_lse` as `[batch, cp_size, heads]`. Reorder the inputs of existing callers.
> - CUDA-core decode raises on `disable_split_kv=True`. Pass `backend="fa2", use_tensor_cores=True` to disable split-KV.

> **⚠️ Upgrade notices (Experimental)**
>
> - `qsa_sparse_paged_attention` with an NVFP4 KV cache on SM100, SM103, SM107 or SM120 needs `backend="cake"` (or `FLASHINFER_ALLOW_EXPERIMENTAL_AUTO_BACKENDS=1`). `flashinfer.experimental.qsa_nvfp4` is removed; call `qsa_sparse_paged_attention` instead.

> **⚠️ Correctness fixes**
>
> - Hopper FP16 and BF16 prefill (single, ragged and paged; the default path on SM90) could write stale values into the attention output. Upgrade if you serve on H100 or H200.
> - Prims-TS context attention with an FP8 (E4M3) V input rounded small attention weights to zero and under-weighted the output. BF16 V was not affected.
