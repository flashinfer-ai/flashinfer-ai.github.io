FlashInfer v0.7.1 brings quantized expert-parallel MoE to Rubin and Blackwell SM12x, runs DeepSeek-V4.1 sparse attention on SM12x, and fuses Kimi K3 speculative verification into one kernel. cuDNN becomes a linear-attention prefill backend on Blackwell, MLA gains a named prefill API with reusable plans, and NVFP4 4over6 recipes can be set per model.

### Quantized expert-parallel MoE runs on Rubin and Blackwell SM12x

Rubin SM107 serves NVFP4 and MXFP8 MegaMoE experts through `MoEEpLayer`, with BF16 combine and output. On Blackwell SM120/SM121, the W4A16 fused MoE shards experts across GPUs through `expert_map`, so multi-GPU workstations such as RTX PRO 6000 pairs can split a model's experts between cards. New CuTe DSL NVFP4 W4A16 and W4A4 MoE backends on SM12x read one prepared expert layout, so a serving stack can choose W4A16 for decode and W4A4 for prefill from a single weight copy; on DGX Spark the W4A16 backend runs a Qwen3.8-Flash-Next MoE layer 1.36× faster than Marlin at one token. The split MoE layer also supports CUDA Graph capture with both NCCL-EP and NIXL-EP.

### DeepSeek-V4.1 sparse attention runs on SM12x, GLM53-NoPE caches shrink 19.5%

DeepSeek-V4.1 sparse MLA runs on SM120/SM121 with a primary FP8 cache and an optional FP4 or FP8 extra cache, each with its own page size and top-k selection, in FP8 or BF16 compute. GLM53-NoPE caches can use compact 528-byte rows, cutting per-token KV storage by 19.5% against the 656-byte padded layout; existing 656-byte pools keep working through strided cache views.

### Kimi K3 speculative verification runs as one fused kernel

`packed_fused_kda_decode` fuses Kimi K3's short convolution, Kimi Delta Attention, and gated RMS normalization into a single launch per verification step on Blackwell SM10x, with ragged batches, accepted-token cache updates, CUDA Graph capture, and FP32 or BF16 recurrent state. In the PR's vLLM integration on eight B300s with speculative decoding, this raised total output throughput by 1.8–3.3% across concurrencies 1–32. NVFP4 MegaMoE also supports Kimi K3's SiTU activation on Blackwell SM10x.

### cuDNN runs Kimi Delta Attention and Gated DeltaNet prefill on Blackwell

Kimi Delta Attention and Gated DeltaNet prefill run on cuDNN's open-source fused linear-attention engine on Blackwell SM100, selected with `recurrent_kda(backend="cudnn")` and `chunk_gated_delta_rule(backend="cudnn")`. The cuDNN backend also runs on CUDA 12 builds; the default Blackwell Gated DeltaNet prefill kernel requires CUDA 13. New `chunk_gated_delta_product` and `chunk_gated_delta_rule2` entry points add Gated Delta Product and Gated Delta Rule 2 prefill on the same engine.

### MLA prefill has a named entry point and reusable plans

`trtllm_prefill_with_kv_cache_mla`, exported from both `flashinfer.mla` and `flashinfer.prefill`, gives MLA prefill its own entry point with the same signature as the decode API. `BatchMLAPagedAttentionWrapper` prepares the TRTLLM-GEN, XQA, and CuTe DSL backends in `plan()` and reuses them in `run()`, so repeated execution and CUDA Graph capture share one lifecycle; on SM100, `backend="auto"` lets `plan()` pick the backend for the planned shapes.

### NVFP4 4over6 recipes are set per model, not per process

NVFP4 quantization APIs and the unified MoE `QuantConfig` accept an explicit `NVFP44Over6Config`, so a serving framework can enable 4over6 from a model's own quantization config and run models with different recipes in one process. The process-wide environment variables remain the default when no recipe is given.

### Upgrade notices

- Install `nvidia-cudnn-frontend>=1.30.0`. The cuDNN linear-attention backend needs the `cutedsl` extra: `pip install -U 'nvidia-cudnn-frontend[cutedsl]>=1.30.0'`.
- `fp8_paged_mqa_logits` and `fp4_paged_mqa_logits` now take `block_tables`, `seq_lens`, and `max_seq_len`, in that order, matching the other paged attention APIs; `num_epi_subtiles` is removed and the FP4 variant's `sf_q` is renamed `q_sf`. Calls using the old names or order raise an error.
- SM90 CuTe DSL MoE: `cute_dsl_fused_moe_bf16` takes `tactic` for tuning, and `CuteDslBf16MoEWrapper` reorders its constructor arguments. Pass `output_dtype`, `enable_pdl`, and `use_fused_finalize` by keyword. `moe_a2a_dispatch` takes `recv_view_cache` by keyword only.
